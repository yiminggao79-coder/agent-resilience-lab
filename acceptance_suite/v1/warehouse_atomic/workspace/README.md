# Warehouse dispatch planner

Finish the small warehouse dispatch planner. Its entry point is dispatch.plan_dispatch(stock, orders). Stock is a mapping of canonical uppercase SKU strings to nonnegative integer quantities. Orders arrive in priority order and have a unique order_id plus a nonempty lines list of {sku, quantity}; quantities are positive integers. You may assume all inputs satisfy those types.

Normalize each requested SKU by stripping surrounding whitespace and uppercasing it, then combine duplicate SKU lines within that order. Process orders in their input order. Reserve an entire order only if every combined quantity is available. An unknown SKU has availability zero. If any SKU is short, reject the entire order without consuming any stock; include every shortage, not just the first. A later order must see only stock consumed by earlier successful orders. Do not mutate either input.

Return {remaining: <stock mapping>, orders: <result list>}. Keep every original stock SKU in remaining, including zero quantities, and never add unknown SKUs. Each result must contain order_id, status (reserved or rejected), items, and shortages. items is the normalized, combined request, represented as a SKU-sorted list of {sku, quantity}. shortages is a SKU-sorted list of {sku, requested, available}; it is empty for a reserved order. Preserve input order for the order results. The existing modules divide normalization, reservation, and orchestration; complete the behavior while keeping this public entry point and schema. Run python3 -m unittest discover -s tests -v. Public tests are immutable.
