# 权限模型与安全边界

这个仓库里的"安全"指一件事：**模型输出、项目文档、笔记与外部扩展，都不等于宿主权限。** 下面写清楚边界在哪里，以及哪些地方只是尽力而为。

## 授权从哪来

| 来源 | 在系统里的身份 | 能否提升权限 |
|---|---|---|
| 用户命令行参数 | 宿主策略 | 是唯一的能力来源 |
| 模型输出 | 不可信输入 | 否 |
| `AGENTS.md` / 项目规则 | 低优先级上下文 | 否 |
| Skills 正文与脚本 | 上下文；脚本需单独审批 | 否 |
| 自动摘要笔记 | 用户级不可信记忆 | 否 |
| MCP server 返回 | 外部受信边界的内容 | 否 |

笔记、规则、外部文本都可能携带提示注入。系统对策不是"让模型遵守规则"，而是在**工具入口**处做参数、路径、版本与权限校验，并在高风险动作前要求精确审批。

## 审批粒度

审批摘要包含：工具名、完整 argv、工作目录、可执行文件身份、以及该次调用在所有后端上的策略合并结果。批准绑定这一份摘要——参数变化、路径变化、可执行文件内容变化都会让旧批准失效。

- 默认 `NoFork`：不创建子进程。
- 实验性 `confined-fork`：owned-group + collector，受管入口，默认关闭。
- 命令运行时用 supervisor + `lease/generation` 防止旧 worker 晚到写入，owner pipe 处理 Runner 死亡与取消。

`permissions.py` 是入口，`process_guard.py` / `native_jobs.py` 是执行者生命周期。

## 沙箱的真实范围

- 原生隔离用 macOS Seatbelt，已在 macOS 14.8.2 / x86_64 验证。
- **Linux 与 Windows 没有等价 backend**。不可用时拒绝执行，不裸跑回退。
- 沙箱保护的是被执行的命令，不是 MCP server 本身。MCP 属于显式受信外部边界，操作者必须自己信任它。
- read-only 保护模式不允许启用无法约束的 MCP。

## 已知不承诺的东西

- 不承诺外部 exactly-once。checkpoint 与文件系统不共享事务，未知效果一律 `needs_confirmation`。
- 不承诺杀死任意时刻都安全。恢复证据只覆盖"摘要已提交、无工具执行中"的 ready 边界。
- 不承诺进程树完全静止。Runner 退出不等于所有子进程已终止，未知 job 走隔离而不是自动解锁。
- 不承诺撤销已产生的副作用。它只保证不会静默重复。
- 有限 Python judge 不防恶意反射；文件对账不覆盖 ACL / xattr。

## 凭据与私有数据

- 凭据只注入明确配置的端点 HTTP worker，项目工具进程使用干净环境，不继承 Key。
- 凭据不写入命令参数、配置、Trace 或 Git。
- `.lab/` 存放私有历史、checkpoint 与费用账本，永不进入版本库。
- 公开的 `evidence/` 只包含有意导出的合成产物与脱敏记录，哈希不为了"看起来干净"而重写。
