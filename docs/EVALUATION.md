# 评测与结果

Agent 的"看起来能用"和"确实做完"之间隔着一整套判定。这份文档记录我用的评测方法、真实跑出来的数字，以及每个数字**不能**推出来的结论。

## 证据分层

四层证据严格分开，不互相顶替：

| 层级 | 内容 | 能证明 | 不能证明 |
|---|---|---|---|
| L1 离线契约 | `tests/` 里的状态机、存储、协议、工具契约与故障注入 | 机制在给定输入下的行为 | 真实模型会不会这样用 |
| L2 本地 HTTP 契约 | loopback 上的三协议 wire 级用例、SSE 分片、随机 receipt 回传 | 客户端解析与完成门控正确 | 供应商端点行为 |
| L3 真实模型任务 | 官方 DeepSeek 端点的多轮 Coding | 真实 LLM 在真实工具反馈下能推进 | 通用成功率；样本量太小 |
| L4 冻结验收 | 曝光前封存的任务 + 不可变工作区 + 逐阶段外部 oracle | 指定任务在指定资源下的完成情况 | 统计独立性；换个领域还成立 |

每次运行都记录阶段、模型、协议、usage、费用上界估算、工具序列、外部判定与局限。失败与 unknown 一律保留。

## 冻结验收：2 项目 × 4 轮

两个全新领域，每个领域四轮连续需求，同一 Session、不同 Turn、不同 Runner PID。每轮都要跑：受保护原测试、全量测试发现（含模型新增的测试）、当前及此前所有外部行为观察，并校验原测试与无答案适配器的字节未变。

| 合成项目 | 四轮需求演化 | 各轮请求数（含摘要） | 自动摘要 |
|---|---|---|---|
| 标量关系表工具 | 左连接/汇总修复 → 命名聚合与稳定排序 → 分区窗口计算 → 命名关系查询流水线及血缘 | 12 / 8 / 26 / 48 | 12 代 |
| 音符事件工具 | 跨八度音高与排序修复 → 精确时间变换 → 轨道重复裁剪 → 分段速度到微秒命令渲染 | 12 / 21 / 21 / 24 | 11 代 |

结果：**72 个最终外部观察、跨八阶段 180 个累计观察全部匹配**；两项目各 12 个原测试方法全程未改动。各项目最终实现修改所对应的模型请求，都能追溯到当时实际安装的自动笔记——不是"最终 state 里存在笔记"这种弱判据。

实际用量：**172 次模型请求，3,393,135 输入 / 205,704 输出 token，0 次未知**；228 次工具执行尝试。按记录的峰时未命中缓存费率估算 **¥8.431902**——这是估算，不是账单，也不是项目总成本。第一个项目末轮用了 48/50 次请求，余量很小。

## 崩溃恢复：真实 SIGKILL

在摘要已提交、没有工具正在执行的 ready 边界，对自有 Runner 实际发送 `SIGKILL`：

- 退出码 -9，PID 87643 → 87652；
- 新进程打开同一归档与笔记，旧 operation ID 没有被再次启动；
- 之后模型继续修改 `allocation.py` 并通过全部检查；
- 六代摘要源游标 33 → 52 → 63 → 69 → 75 → 80；摘要输入 31,532 字节可容纳，完整合格历史 72,674 字节超出 32,000 预算——说明走的是"最大完整可容纳前缀"，而不是在短历史上演示接口存在；
- 38 次请求、457,106 输入 / 28,204 输出、0 unknown、估算 ¥1.139844。

这条证据只覆盖**所测的 ready 边界**。它不覆盖任意崩溃点，不承诺外部效果恰好执行一次，也不阻止模型之后主动提出语义相似的新操作。

## 全仓回归

`python3 -m unittest discover -s tests -t . -v`：**1139 项、0 skip、877.967 秒、exit 0**。仓库里包含 loopback HTTP、真实原生进程与故障注入，需要 macOS 执行条件；受限环境下的失败不算模型质量问题。

## 保留的失败

评测记录不擦除历史：

- 早期 context 验收 v1 为 **1/2**；v2、v3 为 **0/2**。
- 实用配置下的 v4 正式成绩 **0/2**，根因是形状正确的可选 Git 请求被误算为连续无效调用。首版用 Python 异常子类修复，跨 worker 序列化时丢了类别，仍然失败；之后又复现了"缺失 Repo 掩盖坏路径"。两项都是先写 RED 再修。
- 修复后的 2×4 回归通过只算诊断；v5 才是换代码后的新冻结验收。原 v4 的报告与候选 diff 一字未改。
- 历史上不可复现的 TLS / 用量未知记录保持 unknown。新运行的 0 unknown 不能抹掉旧的不确定性。

## 口径说明

- `thinking128k` 指 131,072 **字节**工作窗口 / 32,000 字节摘要输入 / 16k 输出，不是 128k token 窗口。
- 每 Turn 上限：50 请求 / 900 秒 / 180 秒模型 / 12 秒工具 / 最多 6 次摘要。
- 两个合成任务是在同一环境内做角色分离编写的，不构成外部统计独立样本，不能换算成"通用编程成功率"。
- 有限 Python judge 不防恶意反射；AST 与被调用模块的绑定不证明每个变化节点都执行，也不证明摘要语义无损。

## 复现

```sh
python3 -m unittest discover -s tests -t . -v
python3 -B evaluation/context_mission_v5/verify_freeze.py
```
